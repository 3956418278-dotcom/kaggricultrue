# Repository orientation

Build a decision-ready baseline, not an exhaustive inventory.

1. Read the repository `AGENTS.md`, its shared core, and the authoritative documents to which the entry point routes.
2. Inspect working-tree status before interpreting files. Preserve uncommitted user work and distinguish it from the accepted baseline.
3. Inspect the smallest useful set of entry points, configuration, tests, and generated-artifact boundaries needed to understand the current task.
4. Use history, old branches, archives, logs, and external sources only to answer a concrete unresolved question. Verify that historical material still applies before treating it as current.
5. Identify:
   - the present goal or requested outcome;
   - maintained capabilities and their owners;
   - accepted contracts and decisions;
   - the unresolved issue that limits progress;
   - relevant environment, data, permission, or evidence constraints.
6. Return a compact working baseline and the next meaningful decision or action. Record it durably only if it changes maintained project knowledge.

Stop expanding the search when additional context would not change the current decision.
